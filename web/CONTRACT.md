# The page's DOM contract

The server renders every page as plain HTML (docs/HANDOVER.md §18). The files
in `web/` style it and add behaviour. **Everything important works without
JavaScript**; JS adds ⌘K, "Show me", hiding, live template islands, the menus
and live reload. No build step, no framework, no web fonts.

Budgets (asserted by a test): all `web/*.js` together ≤ 40 KB, `web/*.css`
together ≤ 25 KB, uncompressed. The CSP is
`default-src 'none'; script-src 'self'; style-src 'self'; img-src 'self' data:;
connect-src 'self'; frame-ancestors 'none'; base-uri 'none'; form-action 'self'`,
so: **no inline scripts, no inline `style=` attributes, no `eval`**, no
external requests. Set styles with classes; use `el.hidden`,
`classList`, `dataset`.

## Files

| file | served at | what |
|---|---|---|
| `web/app.css` | `/assets/app.css` | the stylesheet |
| `web/theme.css` | `/assets/theme.css` | **generated by the server**, not in web/: `:root { --accent: #d9541e; }` from `ui.accent` |
| `web/app.js` | `/assets/app.js` | ES module entry; imports the others with relative paths |
| `web/*.js` | `/assets/*.js` | further ES modules |
| `web/icons.svg` | `/assets/icons.svg` | SVG sprite: one `<symbol id="NAME" viewBox="0 0 24 24">` per icon |

## A link (`LINK`)

```html
<a class="link" href="https://argo.staging.acme.example" data-ref="acme-infra/argo-staging" id="acme-infra/argo-staging">
  <svg class="icon" aria-hidden="true"><use href="/assets/icons.svg#refresh"></use></svg>
  <span class="label">Argo CD</span>
  <span class="note">argo.staging.acme.example</span>     <!-- optional -->
</a>
<a class="what" href="/e/acme-infra/argocd?s=platform" title="What is this?">?</a>   <!-- optional, only when the link has an entry -->
```

- `id` is the link's ref, only on the **first** occurrence on the page (a link
  may be placed twice). JS finds links by `[data-ref="…"]`.
- The `<a class="what">` sits next to the link (same `<li>`); show it on hover
  or focus of the `<li>`, always visible on touch (`@media (hover: none)`).
- Links open in the same tab (no `target`); they are normal anchors.

## Islands (`<main>`)

On `/s/<space>` main holds islands in order. On `/s/all` the islands of every
space are grouped:

```html
<section class="space-group" data-space="platform"><h2 class="space-title">Platform</h2> ISLANDS </section>
```

### Cards

```html
<section class="island cards" data-ref="acme-infra/environments" id="island:acme-infra/environments">
  <h2>Environments</h2>
  <button type="button" class="eye" data-hide="acme-infra/environments" aria-pressed="false" title="Hide">👁</button>
  <div class="card-grid">
    <article class="card tone-danger" data-ref="acme-infra/environments/production">   <!-- tone-danger | tone-warn | (none) -->
      <h3>Production</h3>
      <button type="button" class="eye" data-hide="acme-infra/environments/production" …>👁</button>
      <ul class="links"><li>LINK</li> …</ul>          <!-- links without a section, first; omitted if none -->
      <h4>apps</h4><ul class="links"><li>LINK</li> …</ul>
      <h4>tools</h4><ul class="links">…</ul>
    </article>
    …
  </div>
</section>
```

Sections with no links are omitted. An empty card shows `<p class="empty">—</p>`.
The Unsorted island has the extra class `unsorted`.

### Links island

```html
<section class="island links-island" data-ref="acme-infra/consoles" id="island:acme-infra/consoles">
  <h2>Consoles</h2><button class="eye" …>
  <ul class="row"><li>LINK</li> …</ul>
```

### Template island

```html
<section class="island template" data-ref="acme-app/previews" id="island:acme-app/previews">
  <h2>PR previews</h2><button class="eye" …>
  <form class="template-form" method="get" action="/i/acme-app/previews">
    <label>PR # <input name="pr" placeholder="1234" required autocomplete="off"></label>
    <input type="hidden" name="s" value="platform">   <!-- the space the island is shown in -->
    <button type="submit">Open</button>
  </form>   <!-- no `pattern` attribute: the server checks the value, so the message is the same with and without JS -->
  <p class="help">Only services the PR deployed exist.</p>
  <ul class="links template-links" data-filled="false">   <!-- server-rendered when filled (on /i/…); empty otherwise -->
    <li>LINK</li> …
  </ul>
  <p class="template-error" hidden>…</p>
</section>
```

With JS: on `input`, fetch `GET /i/acme-app/previews?pr=1234&format=json` →
`{"ok": true, "links": [{"label","url","icon"}]}` or `{"ok": false, "error": "…"}`;
render the links into `.template-links` (as LINK markup, built with DOM APIs,
never `innerHTML` with server strings) or show the error. Debounce 200 ms.
`#acme-app/previews:pr=1234` in the page URL pre-fills and fills it on load.

## Hiding (edit mode)

- `✎` toggles `document.body.classList.toggle("editing")` and `aria-pressed`.
  `.eye` buttons are only visible while `body.editing`.
- Every island, card and **link `<li>`** can be hidden. Link `<li>`s get their
  eye from JS: in edit mode, add `<button class="eye" data-hide="<link ref>">`
  into each `li` that holds an `a.link` (once).
- Hidden refs live in `localStorage["firelight:v1:hidden:" + space]` as a JSON
  array of refs (`space` = `html[data-space]`). Wrap every read and write in
  try/catch; without storage everything shows.
- A hidden element gets the class `is-hidden` (CSS: `display:none`, but in
  edit mode it shows dimmed, with its eye pressed, so it can be unhidden).
- `.hidden-count` shows the count and is visible only when > 0. It opens the
  hidden dialog: a list of hidden items (their visible text, or the ref) with
  an Unhide button each, and Reset.
- Hiding is per space; `/s/all` has its own list.

## Element ids

Three namespaces that can't meet: heading slugs are lowercase and never contain
`/` or `:`; links are `<repo>/<id>`; islands are `island:<repo>/<id>`.
Firelight's own dialogs start with a capital letter (`Palette`, `Info`, `Hidden`).

## ⌘K search

- Open with ⌘K / Ctrl+K, or `/` when focus isn't in a field; also when the
  header search input gets focus (then move focus into the palette).
- Query: `GET /s/<space>/search?q=…&format=json` (debounced 120 ms; on
  `/s/all` and entry pages without a space, `<space>` is `all`) →

```json
{"hits":[
  {"kind":"guide","ref":"acme-infra/request-access","title":"Request access rights","repo":"acme-infra",
   "summary":"…","heading":"What it does not do","url":"/e/acme-infra/request-access?s=platform#what-it-does-not-do"},
  {"kind":"link","ref":"acme-infra/access-portal","title":"Access","repo":"acme-infra","summary":"",
   "url":"https://access.acme.example","show":"/s/platform#acme-infra/access-portal"}
]}
```

- Each result row: kind label (GUIDE / CONCEPT / LINK / REPO), title, repo,
  summary (one line, ellipsis). Links also get a "Show me ✨" chip (a click
  target for the mouse, not a control); Shift+Enter does the same from the keyboard.
  Arrow keys move the selection (`aria-selected`), Enter opens `url`, Esc closes.
- Hidden refs of the current space sort to the bottom of the results.

## "Show me"

Going to `/s/<space>#<link ref>` (from the palette or an entry page's
`a[data-show]`): on load and on `hashchange`, find
`[data-ref="<ref>"].link`, unhide it for the moment if hidden, scroll it into
view (`block: "center"`), and add class `glow` for 2 s (a pulse in the accent
colour; with `prefers-reduced-motion: reduce`, a steady outline instead).

On entry pages, a markdown `link:` renders as
`<a class="link-ref" href="URL" data-show="/s/platform#acme-infra/access-portal">the access portal ✨</a>`;
JS adds a small "Show me" control next to it (or on click with a modifier,
your choice; keep the plain click opening the URL).

## Live reload (`firelight preview` only)

When `<meta name="firelight-live" content="7">` is present (7 = the content
generation), poll `GET /__live` every 1 s → `{"generation": 7}`; when it
differs, `location.reload()`. Stop when the tab is hidden; resume on
visibility.

## Look (D11)

Plain, warm, accessible:
- System font stack (`system-ui, …`), monospace for code. No web fonts.
- Light: near-white warm background, dark ink; dark mode: dark warm grey, light
  ink. `--accent` (from theme.css) for links' hover, focus rings, the glow,
  active tab. WCAG AA contrast in both.
- `data-theme="auto"` follows `prefers-color-scheme`; the ◐ button cycles
  auto → light → dark, stored in `localStorage["firelight:v1:theme"]` and set
  on `<html data-theme>` (`light`/`dark` override the media query).
- Cards flow in a responsive grid (`repeat(auto-fill, minmax(16rem, 1fr))`);
  at 375 px everything stacks, **no horizontal scroll** (long notes and URLs
  ellipsize or wrap).
- `.tone-danger` card: a red-ish top border; `.tone-warn`: amber.
- Notes in grey, small. Kind labels small caps.
- Visible focus rings everywhere. Respect `prefers-reduced-motion`.
- The header bar stays compact; the top row of links is a horizontal list that
  wraps.
